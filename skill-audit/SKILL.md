# Skill Audit — Agent Skill 质量审计

## 核心区分

Prompt 中有两类内容，效果截然不同：

| | 技术事实 | 经验推断 |
|---|---|---|
| 是什么 | 工具能力、客观限制 | 分类偏好、优先级判断 |
| 效果 | 推理**原料** | 推理**天花板** |
| 例 | "凭记忆构造的 URL 参数不可靠" | "所以应该优先走 UI 操作" |

**只给事实和约束，策略让 AI 自己权衡。**

## 五项检查

### 1. 事实 vs 推断混淆

```
BAD:  "URL 是实现细节，UI 是约定"        → AI 硬编码为：必须走 UI
GOOD: "凭记忆构造的 URL 参数不可靠，需验证" → AI 按场景自行判断
```

问：**这是客观限制，还是我从限制推出来的偏好？**

### 2. 行为锚定

```
BAD:  "像人一样浏览网页" → 模拟鼠标轨迹，11 步
GOOD: "像人一样思考"     → 保留策略性，执行自由，3 步
```

问：**描述的是"怎么做"还是"怎么想"？**

### 3. 过度详细

```
BAD:  "Step 1: 打开首页 → Step 2: 找搜索框 → Step 3: 输入关键词 → ..."
GOOD: "目标：在 X 平台搜索账号 Y，获取主页信息"
```

问：**删掉步骤只留目标，AI 能否做得更好？**

### 4. 排他性分类

```
BAD:  "你可以用这些通道：A / B / C"（暗示选一个）
GOOD: "可用工具：A、B、C，可组合使用"
```

问：**用词是否暗示排他？** "通道/模式/路径" → 换成 "工具/能力/选项"

### 5. 自由度匹配

| 任务脆弱性 | 自由度 | 写法 |
|-----------|--------|------|
| 多种方案皆可 | 高 — 目标+约束 | "实现 X，注意 Y 限制" |
| 有推荐模式 | 中 — 模板+示例 | "推荐 A 模式，参考示例" |
| 操作脆弱 | 低 — 具体脚本 | "执行以下命令..." |

## 审计输出

对目标 Skill 逐句标记「事实/推断」，对每条推断执行五项检查，输出报告：

```markdown
## Skill 审计报告：{skill-name}

### 总览
- 事实 / 推断条目比
- 自由度评估：偏高 / 适中 / 偏低

### 发现
| # | 位置 | 问题类型 | 原文摘要 | 建议 |
|---|------|---------|---------|------|

### 改进建议
（按优先级列出改写建议，或输出改进后版本）
```

## 写 Skill 自检

- [ ] 每条指令是事实或约束，不是替 AI 做的决策
- [ ] 锚定思维层面，不是行为层面
- [ ] 目标清晰，无多余步骤
- [ ] 用词不暗示排他
- [ ] 详细程度匹配任务脆弱性
