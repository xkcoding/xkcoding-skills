# 写打分器

循环里只有打分器决定几十轮之后会得到什么；agent 换一个、prompt 改一遍，影响都远小于分数定义里的一个字。

## 契约

可执行文件，从仓库根运行，stdout 打印**一个 JSON 对象**：

```json
{
  "score": 155.95,
  "version": "5.1.0",
  "details": {"cases": 90, "redundant": 2, "pairs": "1879/1904"},
  "remaining": ["gauge.orientation=vertical", "gauge.showThresholdMarkers × calcs=last"],
  "timings_ms": {"observe": 228000, "judge": 516000}
}
```

- `score`：数字，默认越大越好（`research.json` 的 `direction: "min"` 反过来）。
- `version`：必填。runner **只在同一版本内比较**；改了 `score` 就 bump 它，否则新旧尺子的分会被直接比较。改完不用重启：runner 下一轮用新的，并先在 HEAD 重测一次作为新版本的基线。
- `details`：任意 JSON，报告展示给人看"分数怎么来的"。
- `remaining`：字符串数组，原样进下一轮的 prompt（截到 200 条）。
- `timings_ms`：可选，自报子阶段耗时。

退出码非 0、stdout 不是 JSON、缺 `score` 或 `version` → 这一轮记为 **error**（不占 discard 配额，连续几次就停）。

环境里有 `AR_REPO`、`AR_SUBJECT`、`AR_ROUND`、`AR_CHECKPOINT`、`AR_ARTIFACT_DIR`；中间文件写到 `AR_ARTIFACT_DIR`，**不要写进仓库**——仓库里的任何新文件都算这一轮的改动。手跑时这些变量不存在，打分器要能没有它们也跑。

`gate` 是另一个可执行文件：退出码 0 通过，否则这一轮 crash 且不打分。放"连测都不值得测"的检查（编译、lint、schema、冒烟）；它每轮都跑、agent 也会随时跑，要快。

## 开循环之前手跑三次

1. **合不合契约**：`./autoresearch/subjects/<name>/score`，stdout 只有一个 JSON。
2. **分得出好坏吗**：拿两个已知一好一坏的版本（两个 commit，或故意删掉一半测试）各跑一次，差距对得上直觉吗？差 0.01 而你觉得天壤之别，就是不敏感——循环会在噪声里"进步"。
3. **一轮能推多少**：强模型一轮合理的工作量能把分推多远？推不动（分数只在整个功能完成时才跳）agent 没有梯度；一轮推到顶，第二轮无事可做。真实踩过：一个"覆盖 12 个特性和 66 个两两组合"的打分器，第一轮 4 条巨型用例就打满；加了"单条用例最多算 4 个特性"的上限才变成几十轮的研究。

## 三个真实的坑

- **没有分项的维度不会得到投入。** 想要更快就得有耗时项，想要更少冗余就得有冗余扣分；你没打分却在意的东西，几十轮后一定变差。
- **组合覆盖给低权重。** 单项 ×1、两两组合 ×0.05：组合数是平方级的，权重高了 agent 只堆组合不补单项。
- **重复要扣分，且扣得比能骗到的多。** 否则"再写一条等价的"永远是最省力的涨分方式（示例里 −2 对 +0.05）。

## `remaining` 怎么写

从度量里直接导出，不另写一套：

| 度量 | `remaining` |
|---|---|
| 覆盖率 12/66 | 没覆盖的那些的名字 |
| 测试通过 48/55 | 失败的 7 条，各带期望与实际 |
| 延迟 p95 = 820ms | 最慢的几个端点与耗时 |
| LLM 评分 7.2/10 | 评委扣分的具体条目 |

写不出来，说明这个分数是黑箱。空清单意味着"按这把尺子没事可做"，循环会一路 discard 到停。

## 保护分数

`locked` 挡直接作弊：改到锁定路径就 crash、不打分。`autoresearch/**` 永远在；把一切改了就能让分数虚高的东西也放进去（参考实现、期望输出、评测集）。

它挡不住"把答案硬编码进实现"，那是打分器自己的事：期望值由锁定目录里的参考实现现算，不读 agent 写的那份；两个 subject 互相锁（写用例的不能碰实现，写实现的不能碰用例）；怀疑时看报告里的 `changed_files` 和自述。

## 用 LLM 当评委

只有模型能判断的事（文风、"这段解释清楚吗"）可以交给评委，代价要知道：**贵且慢**（见过评委 8.6–17.7 分钟、agent 才 6.6 分钟的研究，用 `timings_ms` 单独报出来）；**有随机性**（固定 temperature 与 prompt、多次采样取中位、粒度做粗到 1–5；runner 只保证分数相等算 discard，不替你去噪）；**能被讨好**（能确定性计算的都算出来，只把真正主观的那一点给评委）。
